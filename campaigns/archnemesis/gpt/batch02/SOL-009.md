# SOL-009 · Independent low-RAM ISO rebuilds

**The stock build failed the cross-directory byte comparison.** Two clean builds at `7c99d2faf` produced matching Linux kernels and initramfs payloads. The final ISOs differed. An independent Limine rebuild at the same absolute scratch path produced matching bootloader payloads and matching final ISOs.

Gemini M12, M13, M16 and M20 cover production build and release tooling. This check used a separate pair of clean detached worktrees, private build directories and verification scripts. It changed no production recipe.

## Evidence

Both clean runs started without compiled inputs. They verified the Linux, musl, BusyBox, dash and Limine archives against `sources.lock`, built the userspace and bootloader, built the low-RAM Linux kernel and packaged the ISO. Both used the same NixOS host toolchain (GCC 16.2.0, LLVM 21.1.8, Rust 1.99.0, xorriso 1.5.8.pl02), three jobs per build and the locked epoch `1767225600`.

The stock ISOs differed in 27,782 bytes. Their Limine BIOS artifacts differed while their Limine UEFI images matched. The 24,704-byte uncompressed BIOS stage 2 differed on exactly the 20-byte linker build ID at offset `0x5a0c`, confirmed against Limine's emitted build-ID files. The ELF debug information contains the distinct build paths. The ID change propagated into compressed BIOS boot data. Experimental compiler path mapping, with and without the NASM flag override, still yielded different BIOS images.

For the successful control, each stock build supplied its own identical kernel and initramfs. Limine was independently recompiled from the pinned archive twice at one canonical absolute scratch path. The first completed directory was moved to evidence before creating a fresh second directory at that same path. The two BIOS payloads and final ISOs then matched byte for byte. This confirms build-path sensitivity. The stock cross-directory reproducibility gate remains open.

Both stock images reached a fresh serial shell and powered off under QEMU BIOS at 9 MiB configured RAM. After a 40-second settle, they reported 3,856 and 3,852 KiB used of 4,416 KiB visible, and PID 1 RSS of 36 and 32 KiB. The byte-identical control image separately passed a 9 MiB BIOS and a 128 MiB UEFI shell and clean-poweroff smoke test with a five-second settle.

## Reproduce

From each of two clean worktrees at the pinned commit, run the first helper with the shared directory of pinned **source archives** and a new output directory per run. Then compare the two clean outputs. For the control, run the second helper from each worktree in sequence, providing the same new scratch path and a new evidence destination for each run.

```bash
bash /path/to/sol009-build.sh "$archives" "$private_build"
bash /path/to/sol009-limine-control.sh "$private_build" "$fixed_scratch" "$control_result"
cmp "$result_a/lowram/out/l2-lowram.iso" "$result_b/lowram/out/l2-lowram.iso"
```

The helpers are adjacent to this report. The raw build logs, xorriso system-area reports, experimental flag runs and guest boot logs are under `batch02/evidence/sol009` beside the coordinator worktree. The experiment covers the low-RAM image on this host and toolchain.
