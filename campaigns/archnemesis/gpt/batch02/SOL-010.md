# SOL-010 · 72-hour endurance infrastructure

**Infrastructure validated. The 72-hour run is pending.**

This check uses the existing stability harness from Batch 01 commit `7c99d2faf` and the pinned 8,636,416-byte core ISO. Gemini M19 and M20 own their harness and release-gate work. Second Front exercised the existing interface from its own worktree and added a campaign preflight only.

## Pilot evidence

- KVM ran two clean boots at 32 MiB and two at 256 MiB, with a 36-second soak per size. The overall screen returned 0 after 188 seconds.
- Each profile recorded four soak samples as well as idle and post-stress samples. CSV and JSONL agreed on all 12 timestamps. Soak used RAM ranged from 5,872 to 6,468 KiB. All eight soak samples reported 40 KiB PID 1 RSS.
- The disposable ext4 image passed write verification, clean reboot, simulated power loss, offline repair and post-recovery writes.
- The screen left `release_gates_satisfied` false. The 18 existing harness unit tests passed.
- A separate invocation with the full 100-boot and 72-hour options received SIGTERM once the first boot began process churn. It returned 1, reaped the active VM, wrote an incomplete report and left the release gate false.
- The command preflight accepted the expected digest and available KVM. It rejected an incorrect digest and a previously allocated output directory.

## Reproduce and prepare

Run from the campaign checkout. Set `iso` to the tested core ISO and `results` to a new location on a volume with space for serial traces and the disposable ext4 image.

```bash
python3 tools/test-stability.py --iso "$iso" --ram 32,256 --min-ram 32 \
  --boots 2 --soak-hours 0.01 --sample-interval 10 --churn 80 --orphans 8 \
  --stress-seconds 2 --settle 2 --output "$results/screen"

python3 campaigns/archnemesis/gpt/batch02/sol010-preflight.py "$iso" \
  35b21d49d7e3291b47f8dc55f9b89e353bcca137007ae59798bd51c01bfcfd16 \
  "$results/endurance-256"
```

The preflight prints a one-profile 256 MiB command using 100 clean boots, a 72-hour soak, 60-second sampling and filesystem checks. Launch it on a host that can remain available for the soak plus cold boots and filesystem checks. Preserve its new output directory. Confirm the final report records all 100 clean boots, the completed 72-hour duration, a successful filesystem check and a true release gate. A matrix runs the soak separately for each selected RAM size.

For the cancellation check, start the generated command with a new output path, capture its PID, and send SIGTERM after it reports `process_churn_and_orphan_reaping` on the first boot. Verify status 1, incomplete JSON and termination of that run's QEMU child.

Raw evidence is under `batch02/evidence/sol010` beside the coordinator worktree. It contains the short screen's serial logs and memory reports, the interrupted report, the preflight command and rejection output.
