Getting started

L2 is an independent, source-built Linux system targeting x86_64. The console system combines rcl2, musl, BusyBox, dash and L2PM.

Begin with a Linux build host and a checkout of the official repository. Read the build prerequisites before starting.

git clone --single-branch --branch main https://github.com/Maiake-ops/L2.git
cd L2
./l2 deps check

The interactive interface is available through ./l2. The same operations can be run non-interactively.

DOCUMENTATION / 02

Build from source

The build needs a C compiler, make, clang/lld, Rust, kernel development tools, archive utilities and ISO tooling. The dependency helper supports the distributions listed in the project README.

./l2 deps install
./l2 build all
./l2 doctor

deps install installs packages on your host. Review its output and package-manager prompts. Allow time for compilation and approximately 2 GiB of free disk space for the core build, as described in the README; optional components need more.

The core image is written to build/out/l2.iso. Build individual components with ./l2 build musl, ./l2 build kernel or ./l2 build l2pm.

LinuxKernel configured from tinyconfig and the L2 fragment.

DOCUMENTATION / 04

Package management

L2PM builds .recipe files into deterministic .l2p archives. Installing an archive extracts it into a content-addressed store and activates profile symlinks.

./l2 pm build l2fetch --check
./l2 pm list

The project wrapper selects the built L2PM binary and uses build/pmroot. --check performs two builds and compares their hashes.

Explore the recipe browser or download the complete recipe guide.

DOCUMENTATION / 05

Writing a recipe

One key/value assignment per line. Metadata is literal; command values run in separate POSIX shells. This example generates a small executable:

name=hello
version=1.0.0
epoch=315532800
install=mkdir -p "$DESTDIR/usr/bin" && printf '%s\n' '#!/bin/sh' 'echo Hello from L2PM' > "$DESTDIR/usr/bin/hello" && chmod 0755 "$DESTDIR/usr/bin/hello"

compile= requires install=. Legacy build= combines both stages. Do not mix the two styles. Always write package files beneath $DESTDIR.

Recipes execute with your user permissions, without a sandbox. Dependency metadata does not automatically install dependencies.

DOCUMENTATION / 06

Kernel configuration

The base configuration is in config/kernel.fragment. Local adjustments are written to config/kernel.local.

./l2 kernel show
./l2 kernel set CONFIG_HZ_250=y
./l2 build kernel
./l2 doctor

Review dropped configuration symbols in build/logs/kernel-dropped.txt. Hardware support depends on the selected configuration and available firmware.

DOCUMENTATION / 07

Boot and installation

The core ISO uses Limine for BIOS and UEFI. Secure Boot must be disabled for the unsigned bootloader. Test the image in a VM before installing on hardware.

./l2install shared installs L2’s tools into /usr/local on a host distribution. It does not install the whole operating system.

Disk installation erases the selected drive.

Back up your data and verify the device name. Follow the repository’s disk-install instructions; never paste an example device path without checking it.

DOCUMENTATION / 08

Budgets and verification

The core ISO has a default <10 MiB size gate. Memory targets depend on hardware, kernel configuration and available RAM. Targets are not minimum system requirements or universal benchmark results.

./l2 doctor
python3 tools/test-stability.py --iso build/out/l2.iso

The repository includes measurements and QEMU testing instructions with context. This site does not present those results as independently reproduced measurements.

Use l2pm build <recipe> --check to check a package’s reproducibility on your toolchain.
